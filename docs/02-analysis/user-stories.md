# User Stories

All stories describe target behavior, not implemented functionality. IDs trace to [functional requirements](../01-requirements/functional-requirements.md) and [acceptance criteria](acceptance-criteria.md).

| ID | User story | Priority | Requirement links |
|---|---|---|---|
| US-01 | As a user, I want to sign in and sign out securely so that only I can access my account. | Must | FR-01–03 |
| US-02 | As a user, I want to view and edit my profile so that my account information stays current. | Must | FR-04 |
| US-03 | As an Admin, I want to create teams and manage membership so that users collaborate in the correct organization. | Must | FR-05–06 |
| US-04 | As a Project Manager, I want to create and manage a project within my team so that work has a clear boundary and owner. | Must | FR-07 |
| US-05 | As an authorized user, I want to create and update tasks so that project work is actionable and trackable. | Must | FR-08, FR-10 |
| US-06 | As a Project Manager, I want to assign tasks to eligible members so that responsibility is explicit. | Must | FR-09 |
| US-07 | As a team member, I want to see priority, status, and due dates so that I can plan and sequence my work. | Must | FR-10–11 |
| US-08 | As an authorized project participant, I want to comment on a task so that decisions and context are recorded. | Should | FR-12 |
| US-09 | As a Project Manager, I want to apply labels to tasks so that work can be categorized and filtered. | Should | FR-13, FR-18 |
| US-10 | As an authorized participant, I want to attach and retrieve task files securely so that relevant materials stay with the work. | Should | FR-14 |
| US-11 | As a user, I want a dashboard of my accessible work so that I can understand current workload and progress. | Should | FR-15 |
| US-12 | As a user, I want in-app notifications for relevant task activity so that I can respond to changes. | Should | FR-16–17 |
| US-13 | As a user, I want to filter and paginate task lists so that I can find relevant work efficiently. | Must | FR-18 |
| US-14 | As a client application, I want stable validation and error responses so that I can present actionable feedback. | Must | FR-19–20 |
| US-15 | As an Admin, I want to review accounts and manage approved roles and active state so that access remains appropriate. | Must | FR-21 |

## Story refinement

Before sprint commitment, add examples, edge cases, permissions, data constraints, analytics needs, dependencies, and a test plan. Priority labels are provisional and do not imply a release commitment.
